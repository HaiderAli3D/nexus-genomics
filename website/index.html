A source audit of four original datasets and one added source

Four datasets were called
“natural vs. engineered.”
None supplies that general target.

That's a bold claim, so this page shows the work. Rather than force a label onto data that doesn't support it, each dataset was re-targeted to what it genuinely measures. A fifth FELIX Supporting Information source supplies a narrower recorded-event contrast, not a general benchmark. No natural/engineered column was invented where none exists.

Method

How each claim was checked

Every dataset was read from its primary source — the raw files, the schema, the paper that published it — not from the brief's description of it. Each finding was then handed to an independent reviewer whose only job was to try to refute it.

The same test is applied to every source, uniformly: does a natural class exist here at all? Is the label ground truth, or somebody's prediction? Does the field actually mean what its name suggests?

Reframed

Addgene & the Genetic Engineering Attribution Challenge

Every sequence in this corpus is an engineered plasmid; there's no natural class in it to compare against. It can't be “natural vs. engineered” because 100% of it is the “engineered” side. It was converted to lab-of-origin attribution instead (1,314 lab classes) — that's the label DrivenData's own competition actually scores on.

1,314 lab-of-origin classes train_labels.csv header
63,017 labelled plasmids train_values.csv rows
13.15% pooled “Unknown Engineered” 8,286 of 63,017 rows
2,438 labs behind that pool <10 deposits each
The brief called it

Natural vs. engineered plasmids

It actually measures

lab_id — lab of origin, 1,314 classes

Every sequence here is an engineered Addgene plasmid. There is no natural class and there never was one.
See the evidence: what “Unknown Engineered” really means

I7FXTVDP is the pooled “Unknown Engineered” class covering 8,286 rows (13.15%) from 2,438 labs that each made fewer than ten deposits. It sounds like it might mean unlabelled, or natural — it doesn't. It means unknown laboratory, still engineered. Reading it as “unknown or natural” would be exactly the kind of fabricated natural class this project is organized to avoid.

Worth knowing: the source files are gated behind a free DrivenData account and acceptance of the competition rules, which explicitly prohibit redistributing the data or anything derived from it. Outputs stay on the machine that generated them.

IARPA FELIX / GUARDIAN

This is detector output, not ground truth — seven automated agents' predictions, not verified biology. And at the sequence level, only 280 of 1,670 sequences link to any call at all, and every one of those 280 is labeled “engineered.” A binary file built from this would have exactly one class in it, which tells a model nothing. It was converted to genetic part role instead (8 classes: promoter, CDS, origin of replication, and others) — the annotation that's actually reliable in the data.

1,670 sequences with real DNA 1,266,189 bp, parsed from all 340 files
257 / 250 natural / engineered, sample level looks balanced — until you go one level deeper
280 of 1,670 sequences link to any detector call the rest have nothing to attach a label to
280 of 280 of those are “engineered” one class, at the sequence level
The brief called it

Natural vs. engineered, via the engineered field

It actually measures

part_role — 8-class genetic part annotation

A detector that finds nothing engineered emits no feature, so there is nothing for a negative to attach to.
See the evidence: sample-level balance vs. sequence-level collapse

At sample level the corpus looks evenly split (natural 257 / engineered 250). That balance evaporates at the sequence level: only 280 of 1,670 sequences can be linked to a detector call at all, and all 280 of those calls say “engineered.” Two of the eight part-role classes are literally named engineered_region and engineered_tag — but those are part types, not a verdict on the organism. Treating them as a binary “is this engineered” label is exactly the fabrication this project exists to avoid.

Worth knowing: the engineered field is detector output from seven agents that disagree with each other, not experimentally verified biology. It is treated as a prediction, never as ground truth.
Narrow event contrast

FELIX Supporting Information signatures

A fifth source added after the four-source audit.

The Supporting Information records sequences associated with specific engineering events. It supports an event-relative distinction: host-context sequence not introduced by the recorded event versus sequence introduced by that event. That is narrower than a general natural-versus-engineered benchmark and must not be presented as one.

309 labelled rows in the full output 163 class 0 · 146 class 1
26 unsupported records excluded includes all 8 insertion.site records
2 malformed FASTA records quarantined missing a header >, not guessed at
0.754 length-only baseline accuracy the confounder to quote alongside any result
Unsupported shortcut

Every “engineering signature” is engineered sequence

The source supports

0 not introduced by this event · 1 introduced by it

Class 0 is an event-relative provenance statement, not a global claim that a sequence is natural or untouched.
See the evidence: which element types can be labelled

Insertions, plasmid elements and plasmids supply introduced sequence. Flanks and sequence removed by a deletion are host context not introduced by that recorded event. Rearrangements, point mutations and insertion.site records are excluded because the source does not establish either emitted sequence-level provenance class.

Worth knowing: the set is small and strongly length-confounded. The manifest publishes a length-only baseline, and evaluation should group records by the shared FELIX element number. Third-party redistribution rights are not established, so raw and derived files stay local.

SeqScreen & FunSoC

This is a screening pipeline, not a labelled dataset. “Sequence of concern” means “might be pathogenic,” which is a completely different axis from “was engineered” — most flagged sequences are natural toxins and virulence factors. It was converted to 32 pathogenicity-mechanism labels instead (multi-label, one per mechanism).

32 FunSoC labels multilabel, positive-only
0 mentions of “synthetic construct” or “wild-type,” or “provenance” — in the source paper
32630 the one decoy signal NCBI taxid for “synthetic construct”
The brief called it

Natural vs. engineered, via “sequence of concern”

It actually measures

32 pathogenicity mechanisms (FunSoC), multilabel

“Sequence of concern” does not mean “engineered.” The overwhelming majority of sequences carrying one are entirely natural toxins, adhesins and virulence factors.
See the evidence: the one field that looks like an engineering signal

The output column vbeo == 's' is the only field that resembles an engineering flag — and it's a decoy. It fires when a read's taxid falls under NCBI “synthetic construct” (taxid 32630), which flags cloning vectors and artefact GenBank records, not engineered pathogens. An engineered pathogen gene hits its natural homolog and is never flagged by it. SeqScreen is a pipeline that produces annotations; it does not ship provenance labels of any kind.

Worth knowing: FunSoC labels are positive-unlabelled. A 0 means “not a curated positive,” not “verified negative.” Treating zeros as true negatives will overstate precision.
Narrowly supported

CodonTransformer

A matched natural-CDS versus one-generator artifact detector.

Each pair is the same protein, once as a natural NCBI coding sequence and once as CodonTransformer's codon-optimized rewrite. This supports detection of this model's output on its published organism slice; it is not general engineered-sequence ground truth.

622,915 matched natural / generated pairs same protein, same organism, per row
73–94% nucleotide identity, median 81% measured over the 145 untruncated demo pairs
3 / 9 organisms shipped (demo / full) of 17 the model was fine-tuned on — Homo sapiens is 36% of the full file
The brief called it

General natural vs. engineered

=
It actually measures

target: 0 natural NCBI CDS · 1 output from one named generator

Not a general engineered-sequence detector — one generator, identical proteins, and only 9 organisms in the shipped full file.
See the evidence: why the identity spread is the signal, not noise

Both members of a pair encode the identical protein, so the only available signal is synonymous codon choice — which is exactly why a 73–94% nucleotide identity spread (median 81%, measured over the 145 untruncated demo pairs) means something rather than being measurement noise. It will not transfer to output from other codon-optimization tools, and it has no bearing on biosecurity screening; it measures whether a model can recognize this one generator's output, on a narrow slice of life.

Worth knowing: rows strictly alternate natural / generated in the source file, so a naive shuffle or split leaks the label — splits must be grouped by the underlying gene.

The road not taken

What was chosen not to build

Refusing a false label is easy to say and easy to skip once a shortcut is sitting right there. Two of those shortcuts were considered and deliberately left alone.

A constructed Addgene vs. RefSeq set

A large natural-vs-engineered dataset could be built quickly by pairing engineered Addgene plasmids against natural RefSeq or PLSDB sequences. It wasn't. The classes would differ by database, assembly pipeline and GC content as much as by engineering — a model would score well by learning the source, not the biology.

A global claim from event-relative FELIX labels

The Supporting Information distinguishes what a recorded event introduced from host context it did not introduce. Promoting class 0 to “globally natural” or the whole set to a general engineering benchmark would exceed that evidence. Records such as insertion.site are excluded where neither emitted class is established.
